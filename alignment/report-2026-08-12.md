## Ported now

1. **HTML character encoding** — ported raw-byte detection of HTTP charset,
   UTF BOMs, and early HTML meta charset. Origin HTML is decoded with
   `encoding_rs` before DOM parsing; byte, redirect, deadline, and SSRF limits
   are unchanged.
2. **Document base URL** — the first valid `<base href>` now participates in
   content URL and metadata URL resolution, including site-relative base URLs.
3. **JSON-LD metadata** — arrays and `@graph` nodes are traversed; article-like
   nodes are preferred and fill missing normalized title, author, description,
   dates, publisher, language, image, canonical URL, and keywords.
4. **Richer head metadata** — Twitter Card and Dublin Core fallbacks, `og:url`,
   `og:locale`, repeated `article:tag`, and deduplicated keyword sources now feed
   the existing normalized `Metadata` contract.

All four remain native Rust implementation details. The `crawlberg` crate,
CLI, browser, and services are not runtime dependencies.

## Review later

1. **Opt-in article resource inventory** — links, images, headings, feeds, and
   JSON-LD entries could be exposed in a separate typed field, but semantics
   must specify source-page versus cleaned-article scope and explicit caps.
2. **Citation rendering** — a separate renderer could convert links to numbered
   references, but it must derive from canonical clean HTML and cannot mutate
   the article or default Markdown.
3. **HTML media-type validation** — origin responses could reject obvious
   binary/non-HTML bodies earlier. This needs a typed error and compatibility
   decision because permissive servers often omit or mislabel `Content-Type`.

## Intentional skips

See `alignment/known-divergences.md`. The major skips are site crawling,
browser/WAF behavior, whole-page resource inventories, robots traversal,
full-page Markdown pruning, and replacing the proven Markdown engine.
